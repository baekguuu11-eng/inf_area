============================================================
1. EXISTING CHERNOBYL PROBLEMS / ROOT CAUSES
============================================================
- Persistent 6x4 runtime arena grid was deliberately rendered during idle, causing the "grid visible while no attack is active" issue.
- Fixed 6x4 attack geometry prevented page progression from feeling spatially different.
- SafeShift had been improved once, but the page system still did not guarantee page-specific grid scale and all related safe-zone families did not share one reachability rule.
- Pattern count was numerically reasonable but most choices were still variations of "cells telegraph -> cells explode" without strong setup/pressure/finisher roles.
- CombatLoop selected one pattern, waited, selected another; no real combo director existed.
- Anti-burst existed but its trigger time was much shorter than the design target and did not combine sustained-time and cumulative-damage thresholds cleanly.
- Boss hit feedback depended mainly on generic enemy feedback and the core pulse, so rapid shooting did not strongly communicate weak-point damage.
- Debug controls covered page jumps but not direct pattern/combo/counter/grid cleanup/invulnerability testing.

7. PAGE 1 / 2 / 3 DIFFERENCE
============================================================
PAGE 1
- Grid 4x3.
- Large readable cells, long telegraphs.
- Fundamental movement rules: target, cross, checker, line sweep, outer/center movement, split field.
- Combo probability about 32%, mainly 2-step combos.

PAGE 2
- Grid 6x4.
- Adds compression, shockwave, safe shift, delayed timing, moving safe lane, corridor and corner control.
- Combo probability about 52%, 2-3 step chains.
- Anti-burst time/damage thresholds and cooldown are reduced from P1.

PAGE 3
- Grid 8x5. This was chosen instead of 8x8 because the current boss room is much wider than tall; square 8x8 cells would become vertically too small for comfortable player movement.
- Adds rotating lines/sectors, spiral, 3-step safe relay, delayed cascade, reactor cycle and sector collapse.
- Combo probability about 68%, strong 3-step spatial sequences.
- Difficulty comes from information/sequence/space control, not disappearing telegraph time.

============================================================
8. SAFE ZONE UNAVOIDABLE BUG FIX
============================================================
- Safe zones are generated as 2x2 blocks (4 cells), not globally random cell sets.
- The first safe block is selected from candidates reachable from the player's current live position.
- After the first blast, the second safe block is selected again using the player's REAL post-blast position.
- Candidate distance is measured to the safe rectangle itself, not only its center.
- Movement budget uses base PlayerMovement speed (5 u/s) * warning time * 0.84 safety factor.
- Therefore the route is designed to be reachable without requiring Dash. Dash 1.5 provides additional recovery margin.
- SafeZoneRelay uses the same rule for A -> B -> C.
- MeltdownGrid also uses a reachable 4-cell block rather than two arbitrary safe cells.

============================================================
9. IDLE GRID BUG ROOT CAUSE / FIX
============================================================
Root cause:
- V10 CreateArenaGridVisualV10() created CHN_FixedArenaGrid_6x4 and UpdateCoreLightV10 continuously assigned visible alpha while idle/combat.

Fix:
- V11 no longer creates the persistent arena grid.
- Only attack-specific CHN_*Telegraph and CHN_SafeIndicator objects are visible.
- ClearAllGridWarningsV11() centrally destroys telegraph/safe-warning objects.
- Called between attacks, before transitions, debug reset, boss death and OnDestroy.
- Old runtime grid renderer list is also forced disabled as migration defense.
